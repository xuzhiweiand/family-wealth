### 关键设计取舍

- **FDK 在 RPC 层全程只见密文**：create_family 的 p_wrapped_fdk / start_rotation

## 修 useMyFamilyRole 订阅 bug（W6 phase 3 遗留）

### 根因

`useMyFamilyRole` 原来 `const user = useAuthStore.getState().user` —— 只在渲染时读一次，
user 切换（登录/登出/换家庭）不触发重渲染；且 `useFamilyStore((s) => myRole(s.members, ...))`
只订阅 members，user 变了角色即便重算也可能被 Object.is 挡住。

### 修复

```ts
export function useMyFamilyRole(): FamilyRole {
  const user = useAuthStore((s) => s.user);
  const members = useFamilyStore((s) => s.members);
  return useMemo(() => myRole(members, user?.id ?? ''), [members, user?.id]);
}
```

- user 改走订阅（`useAuthStore((s) => s.user)`，项目统一写法）
- auth-store 里 user 是整体替换（`user: result.data!.user` / `user: null`），引用必变，订阅正确
- 4 个调用点（new / index / [id] / [id]/edit）全部自动继承修复，无需改
- store 内部 action 里的 `getState().user` 是事件回调里的命令式读取，是正确的，不动

### 教训

- zustand hook 里 `getState()` 只适合**命令式 action 回调**；**渲染路径**必须走 `useXxxStore(selector)` 订阅
- 修复后此 bug 从"待办"移除；W6 phase 3 遗留剩：真机 UX 验证、删除确认接 RN Alert、详情页迷你图

## ⚠️ 教训：commit `0b40756` 误删 InMemory 文件（已修正为 `2baf233`）

### 发生了什么

`2baf233` 之前有过 `0b40756`——那次 commit 把 db/api 包里 6 个文件标记删除，其中**误删了活的代码**：

- `packages/api/src/in-memory.ts`（`InMemoryAuthClient` 是 bootstrap 实际用的 dev fallback）
- `packages/db/src/in-memory.ts` / `repository.ts` / `index.ts`（仓储接口 + 实现）
- `packages/db/src/__tests__/repository.test.ts`（AssetRepository / SnapshotRepository 测试）

**为什么误删**：`git rm packages/db/src/sync-queue.ts` 之后又 `git add packages/db/src/__tests__/repository.test.ts`。
我前面 Edit 删了 test 文件里的 InMemorySyncQueue describe 块，整个文件就成了"git 视角下的净删除候选"，
`git add` 自动带上了文件本身的删除标记。一并 commit 进去就把整个文件删了。

更糟糕：**用户没看到 packages 被批量删除**（status 之前显示正常），
直到跑测试报 `Cannot find module '../in-memory'` 才发觉。

### 修正流程

1. `git checkout HEAD -- packages/` 恢复工作区
2. 重做 workspace junctions（`node_modules/@family-wealth/*`）—— 沙箱 safe-delete shim 把 junctions 也清了
3. 用 `git checkout HEAD~1 -- <具体文件>` 逐文件恢复误删的 in-memory / repository / index
4. 重新 Edit 注释改动（restore 后注释回到原版）
5. `git reset --soft HEAD~1` 撤销有问题的 commit，重新整理并分两个干净 commit 提交

### 教训（pitfall #36）

- **复合 git add 命令要按文件粒度**：不要 `git add dir1/ dir2/` 把整个目录 stage，
  应该显式列文件 `git add path/to/specific/file1 path/to/specific/file2`
- **commit 前必看 stat**：`git show --stat` 或 `git diff --cached --stat`，发现不预期的删除立刻 `git reset --soft HEAD~`
- **git 不会"只删特定行"**：Edit 删了一个 describe 块后，整个文件就成了"净删除候选"。
  Edit 后的空壳文件**永远不要 stage 进 commit**——除非还有有意义的修改
- **safe-delete shim 的副作用**：误触发后 `node_modules/@family-wealth/*` junction 也清了，
  jest 报"Cannot find module"是症状。修复时先 `ls packages` 看是否物理删了
- **PowerShell 循环脚本异常时 Out-File 不会执行**：第一个 cmdlet 抛异常时后面的日志不会落盘

## 真机验证清单（华为 Mate 40 Pro / API 31 / 无 GMS）

### 真机信息

- 华为 Mate 40 Pro（NOH-AN00），HarmonyOS 4（底层 Android 12 / API 31），**无 GMS**（HMS 替代）

### 关键发现（影响验证方案）

1. **无 GMS → ML Kit 端侧 OCR 不可用**（`@react-native-ml-kit/text-recognition` 依赖 GMS 下发模型）。
   华为这台只能验「降级路径」（`new.tsx` catch → 弹「端侧识别不可用，请手动输入金额」）
   和「解析层」（ocr-lab.tsx 用 extractCandidates 纯 JS，不依赖 native）。
   真实识别需 GMS 设备或 iOS —— 这是 ADR-0008 端侧优先在国内无 GMS 设备的盲区，后续要决策
2. **资产仓储是 InMemory 不持久**：`bootstrap.ts` 里 `assetRepository = new InMemoryAssetRepository()`，
   WatermelonDB 已实现（packages/db/src/watermelon/repository.ts）但**未接入 bootstrap**。
   真机验证默认数据不持久（杀进程资产清零），登录态靠 keychain 可跨重启恢复
3. **bootstrap 需 env**：`EXPO_PUBLIC_SUPABASE_URL`/`ANON_KEY` 不配则走 InMemoryAuthClient（内存 mock），
   测不了真实鉴权/家庭共享 RPC。真机要连真实 Supabase（云项目最省事，本地 start 有局域网 localhost 坑）
