# ADR-0011: OCR 金额解析的准确率回归语料

**状态**: Accepted
**日期**: 2026-09-08
**关联**: ADR-0008（端侧 OCR）

## 背景

ADR-0008 把 OCR 定为端侧优先，并预期真机准确率 70-80%。但真机 prebuild
在当前环境不可用，且「准确率」没有回归手段——解析逻辑改一行关键词权重，
没人知道是变好了还是变坏了。

解析层（`packages/ocr/parse.ts`）是纯函数，不依赖任何 native 模块。
这决定了它可以被离线钉死。

## 决策

建立**标注语料 + 阈值护栏**作为解析层的验收基线：

1. `src/__tests__/fixtures/corpus.ts`：25 条仿真样本，每条是
   「OCR 文本行 + 用户真正想录的金额（分）」，覆盖：
   - 银行借记卡/信用卡/贷款页、券商持仓、支付宝/微信、
     理财、基金、保险、贵金属、数字货币、借出债权
   - 干扰项：卡号（`****`）、日期、手机号、收益率/年化/净值/
     万份收益、涨跌幅、授信额度、月供
   - 难度分级：easy（金额与关键词同行）/ medium（分离但带 ¥）/
     hard（分离 + 多个同分符号候选 / 全角数字 / 万单位）

2. `accuracy.test.ts` 三层护栏：
   - 每个样本必须产出至少一个候选（连候选都不给 = 功能不可用）
   - **top-1 命中率 ≥ 70%**：用户打开候选列表时第一个就是对的
   - **top-3 命中率 ≥ 90%**：前三名里有正确答案（点选即可）
   - easy 样本 top-1 必须全中（关键词同行的场景不允许退化）

阈值来源：ADR-0008 的端到端目标 70-80% 已含「拍照→识别→解析」全链路，
解析层是纯函数应显著高于此；70% 阈值给真机语料接入留了收紧空间。

## 与真机实测的关系

- 当前基线（25 条人工仿真）：top-1 ≈ 96%，top-3 = 100%
- 真机联调时把真实 OCR 输出按同样格式加进 corpus，阈值随语料
  接近真实分布逐步收紧到 80%/95%
- 语料同时是「OCR 解析层 bug 的复现集」：某类页面识别错了，
  把文本行抄进来就是一条回归用例

## 后果

- ✅ 解析层任何改动（调权重、加关键词、改正则）都有量化验收
- ✅ 无真机也能持续演进解析逻辑
- ⚠️ 仿真语料不能替代真实 OCR 输出的噪声特征（断行、错字、
  漏识别），真机语料接入前不要把阈值调到接近当前实测值
